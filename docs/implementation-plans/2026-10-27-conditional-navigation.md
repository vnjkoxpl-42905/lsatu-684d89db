## Goal and acceptance
1. Every visible home chapter card has a main chapter link, separate Lessons and Drills actions when available, and relevant Flashcards only when authored and permitted. No nested links/buttons. Every lesson in an expandable chapter progress list links directly to that existing lesson. The home also provides one obvious Practice centre link and all-course lessons/drills/cards access.
2. Chapter counts and lesson states are read from the existing CourseProgressProvider, including historical projected completion. Required-step denominator stays unchanged. Read requiredForEditionCompletion only from the edition-adjusted, already-authorized steps supplied by OpeningCourseRoute, never a raw registry flag. Raw arrays are test inputs only after the existing requirements transform. Separate required lesson/drill counts are explicit; optional steps are labelled optional and excluded from required completion. No progress is written by navigation/filtering. In progress is not mastery or completion.
3. Lessons and drills have a labelled Filters button/disclosure with chapter/topic, content type where relevant, and saved progress (all/not started/in progress/completed). Home can filter chapters by progress. Invalid query values safely normalise, empty results offer reset. Existing full course/selected chapter progress remains visible and never recomputed from a filtered subset.
4. Flashcard surfaces expose Filters using existing permitted Topic/Task/Review or deck choices. All authored sets remain discoverable. Lesson return links and chapter context work. No fabricated chapter4-7 decks; hide irrelevant card action instead of linking to an unrelated collection. Card actions open tools/skillPracticeUrl, never chapter-N as a card player. Relevance: an authorized chapter/lesson step with unitId orientation or sufficient-necessary permits foundation; allowedSkillGroups on those chapter/lesson steps yields g1/g2/g3/g4 sentence cards and g1/g2 indicator decks. Intersect those candidates with the full active authorized steps/deck validation. Mixed indicator deck requires both g1 and g2. An orientation-only selection receives foundation only; g3-only receives g3 sentence cards, never foundation, mixed, or a g1+g3 contrast. No groups/decks means no Flashcards action. Native card state keys and ratings unchanged.
5. Existing exact activity targets, skill grants, and editions remain authoritative. Filtering only consumes already-authorized steps/config options. New links retain assignment and edition through existing URL builders. Topic/mode choices cannot broaden an activity grant. Clear new course-list query parameters on navigation to unrelated activities, individual lesson/drill or a different list.
6. Desktop/tablet/phone and docked widths: card actions and progress readable, complete row/card hit areas where semantic, keyboard focus visible, no horizontal overflow. Main chapter anchor is followed by sibling Lessons, Drills, Flashcards when permitted, then the lesson-progress disclosure. Labels for sibling actions include chapter identity; DOM tests prohibit nested a/button elements. CoursePath direct links retain description, optional marker and saved status. Existing warm paper/charcoal design retained. Reduced motion leaves controls/content immediately available.

- Step filter: done => completed; started => in progress; absent, new or any other status => not started. Chapter filter uses required steps from the unfiltered edition-adjusted chapter: completed requires a nonempty required list all done; not started means none has status started or done; in progress means anything else. For zero-required chapters, never completed: classify by optional visible saved started/done (in progress if any, otherwise not started), and label No required steps / Optional instead of 100%.
- FlashcardTools receives the authorized edition-adjusted steps. A from id is accepted only when it identifies a note in those steps. Render Back to [lesson] through url(from) for any such id, including foundation lessons. Unknown or unauthorized from values have no lesson return link; fall back to the existing all-flashcards/course navigation. skillPractice already validates from and retains that validation. No arbitrary URL redirect is accepted.
- Use injected store save and resume spies, not nonexistent method names. Assert zero calls while toggling/changing/resetting filters on list pages. Lesson navigation retains its existing baseline save-on-arrival behavior and does not auto-complete.
