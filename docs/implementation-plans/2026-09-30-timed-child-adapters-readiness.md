# Protected timed children use dedicated official routes

Date: 2026-09-30

The new `timedLrAdapter.ts` and `timedRcAdapter.ts` consume the capability-gated v1 transactional transport. Dedicated `/testing/test/:runId/lr/:legIndex` and `/testing/test/:runId/rc/:legIndex` routes render `TimedOfficialChildRunner` through `timedChildController`. Existing Drill, RC player, legacy session stores and section-history writers do not mount in this branch. Completed legacy report routes remain separate. The foundation, full writer and metadata upgrade are now deployed; the 59-row catalog is seeded and configuration is enabled with a 30,000ms lease. Code integration and isolated tests do not establish live acceptance evidence. #167 remains open until the rollout and live checks are complete.

LR composes `TimedPracticeTestStore`. It restores the exact attributed `PracticeSession` queue, position, first answers, flags, switch count and regulation answer IDs. Before creating a checkpoint or close command it verifies canonical source identity and SHA-256 fingerprints against the immutable parent manifest. It imports the existing pure `normalizeQuestionTextFields` function, now exported with no behavior change. Shared passages, prompt repair and prose normalization therefore use the actual QuestionBank rules. Optional loaded QuestionBank rows must agree with the resulting normalized fields and ordered queue. Canonical input must include the entire source section, including removed positions needed by the normalizer; excluded positions cannot enter the scored queue.

LR checkpoint commands carry typed selected letters, correctness, milliseconds, flags, switch counts, current position and optional regulation IDs. Close commands require the entire ordered matching answer-key set and an analysis object. Prepared commands are durable before transport; retries retain command ID, revision, epoch and the exact payload. Analysis and client-derived correctness retain the scoring trust boundary documented in the foundation plan. The catalog does not provide a new server-secret answer key.

Protected `question_states` retain spent time, flags and eliminations even for an unanswered LR question, without inventing an answer attempt. The official route checkpoints picks/navigation immediately and renews through checkpoints every five seconds. It freezes regulation answer IDs at the cutoff, requires account acknowledgment, and then retains the existing LR overtime mode until explicit Finish. A failed read/save replaces questions with a paused recovery state; an existing pending command can only be retried as the same envelope. Clock estimates remain bounded by the acknowledged server lease. Async generation and owner/run/leg checks prevent delayed prior-route replies from changing another account's view or navigating it.

RC composes `TimedWorkClient`. It restores the exact native question/passage attribution, session ownership and saved first-attempt UUIDs. It verifies passage and question text/choice fingerprints against the immutable RC manifest before exposing loaded content or preparing a command. It converts server child rows into the existing RC session and state shapes, deriving end-of-set reveal and section timing from protected parent state. It requires an explicit device identity; foreign writers, pending recovery and expired leases expose paused state. Preparation also checks the current monotonic sample age, preventing a once-valid view from creating commands after lease expiry. Running display time is capped at the account lease. A paused acknowledged child can close through the v1 command.

RC revisits update the current choice under its stable first-attempt UUID; immutable command receipts preserve acknowledged revisions. Close analysis retains visit/answer-trail and personal marker telemetry in the account session configuration. Both child routes reuse the existing official question/passage panes, retain flags, eliminations, navigation, text size, find, highlights and pause/finish controls, and suppress answer/explanation reveal until the PrepTest returns to its completed report. Per-question dwell accrued while awaiting an acknowledgment is retained rather than overwritten by the older checkpoint payload.

Neither adapter calls a legacy child or parent writer. Capability absence, permission denial, storage failure, malformed source, duplicate attribution or a lost receipt fail closed. A receipt whose parent has advanced to another leg returns no fabricated previous-child view. A future report integration must read the historical acknowledged child or official parent result separately; these adapters never infer a report from an unacknowledged local answer set.
