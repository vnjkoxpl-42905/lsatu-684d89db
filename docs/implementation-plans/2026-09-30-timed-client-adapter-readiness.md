# The v1 client and parent are integrated; the backend is enabled

Date: 2026-09-30.

`src/lib/timedWorkClient.ts` implements the isolated ordinary-auth RPC transport and durable command queue. `src/lib/timedPracticeTestStore.ts` prepares the parent conversion, control commands, lease-bounded display clock, and exact child launch metadata. These transport files contain no legacy writes; the later dedicated route integration below now consumes them.

The owner/run queue keeps the original command UUID, operation, payload, expected revision, writer epoch, and original parent until acknowledgment. A lost reply, write denial, account change, or storage acknowledgment failure preserves that command. A second command cannot replace it. Recovery is deliberate through `retry()`, with no automatic command rebasing or legacy raw-write fallback.

Definite PT401/PT409/PT410 server denials are recorded against the exact pending envelope. `archiveRejected()` performs a fresh owner-safe read, then preserves the command, its answers, rejection, and current authority in the owner/run archive before clearing the active pending slot. This explicit resolution permits a new claim. A lost reply, changed-command replay, authentication failure, or storage failure is not discard proof. Each new transmission clears prior denial proof before sending, so an old rejection cannot discard a later potentially committed command.

Every prepare, retry, refresh, and rejection archive holds a native browser Web Lock keyed to owner/run. Compare-and-swap remains a consistency check inside that actual cross-context reservation, rather than an atomicity claim for localStorage itself. Unsupported locks or failed durable storage block sending. Private unlocked helpers prevent nested-lock deadlock during recovery and stale-receipt refresh. Unit tests inject a shared lock coordinator to exercise two independently constructed clients; production defaults to `navigator.locks`.

`prepare()` checks the ordinary actor and operation payload before preserving a request. `retry()` checks the actor before capability discovery, before the command, and after its reply. Unsupported version, missing capability, inactive mutation capability, or an unadvertised operation blocks writes. The RPC entry points are `create_timed_practice_test_v1(p_command)` and `commit_timed_work_v1(p_command)`. Public operation payloads match the SQL writer, including the empty-payload `heartbeat` for running sections and breaks.

The acknowledgment must bind owner, work kind, run, command UUID, operation, full original envelope, and the exact committed revision. The current parent must carry protected v1 control fields and the same immutable full content manifest/hash, section budget, lease budget, and frozen leg definitions. Current checkpoint attribution and ordered LR queue or RC passages are checked against that parent. Old receipts can acknowledge their original command while returning newer authority; a delayed older parent does not overwrite a newer saved parent or checkpoint. Stale reads and contradictory same-revision reads reject without storage writes. A valid older receipt is saved before a fresh authoritative read obtains the correct server-time sample; an older sample is never silently paired with a newer clock anchor.

`refresh()` reads `read_timed_practice_test_v1(p_work_id)` as one owner-safe account snapshot. Read capability remains available for protected history while mutation capability is disabled. Reads preserve the pending envelope and its original authority, so a later leg cannot reinterpret a lost-reply checkpoint as a new command. The latest received receipt is retained with the acknowledged parent.

The parent adapter maps authoritative identity, timing accommodation, device/revision, leg results, and break state to `PracticeTestRun`. It does not adopt or rewrite legacy rows. Its clock is a display estimate anchored to server time, advanced using `performance.now()` rather than the adjustable wall clock, and bounded at the acknowledged lease expiry; it does not claim an offline pause reached the server. Pending recovery, a different device, or expiry blocks child launch. Missing or contradictory frozen child content fails instead of generating a replacement queue.

Validation: focused transport/parent tests and changed-file ESLint pass; full application typecheck passes. These tests use mocked ordinary-auth transport responses and browser storage. They establish client boundary behavior, not deployed backend transaction or production acceptance evidence. The separate real PostgreSQL harness owns backend evidence.

The original client-only slice performed no deployment or activation. Later coordinated integration and backend deployment are recorded below; frontend publication and ordinary two-device/outage/revocation acceptance remain open.
