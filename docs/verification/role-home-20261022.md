## What changed

- **Role dispatch** (`src/components/classroom/home/ClassroomHome.tsx`). Home picks
  teacher or student from the `user_roles` admin role resolved for the current
  actor. Until that read succeeds, neither Home mounts: a neutral skeleton shows,
  or a retry on cold failure. After it resolves, a background failure keeps the
  mounted Home and shows a quiet "did not refresh" notice. The Home is keyed by
  `resolvedFor`, so an account switch remounts it.
- **Permissions** (`src/hooks/useUserPermissions.ts`). Additive fields `resolved`,
  `resolvedFor`, `isError`, `error`, `retry`. Existing fields are unchanged.
- **Teaching desk** (`home/teacher/`). New model, adapter and view. It shows a
  greeting and date, one ink "Assign work" action (`/teacher/library/assignments`,
  plus `/teacher/students`), unread conversations (`/teacher/inbox/platform:<id>`),
  upcoming `student_sessions` (to `/teacher/students/<id>/schedule`) and a roster
  summary. Each region has its own loading, error-with-retry and empty state.
  Query keys carry the actor id and only run for a resolved admin. It does not
  mount the Desk task queue, so Gmail and Calendar sync are not started.
- **Student Home** (`ClassroomHomeView.tsx`, `useClassroomHome.ts`). One featured
  next action on the ink surface (the earliest real deadline). The "Up next" list
  leaves out that exact key, and the full open count stays in the summary. The
  decorative Open and Rest week labels are gone. The badge uses the canonical
  unread-conversation total. Briefing, launch, Mark done, Report Card and access
  gates are unchanged.
- **Freshness** (`useHomeFreshness.ts`). Only while Home is mounted, a
  `focusManager`/`onlineManager` regain invalidates the actor's assignment keys.
  There is also a manual Refresh. No realtime subscription to assignments and no
  polling.
- **Motion** (`useHomeEntrance.ts`). One GSAP fade-up and stagger across top-level
  regions, with no blur. It runs once per mount and is skipped if the content is
  ready more than 700 ms after mount. It respects reduced motion. The Home root
  carries `data-motion-skip`, so the shared classroom reveal does not animate it
  twice.
- **CSS** (`home.css`). About 2,070 lines of stacked overrides were replaced with
  one scoped sheet (about 900 lines) on classroom role variables. It works in light
  and dark, uses container queries (so it reflows when the sidebar docks), and
  gives 44 px targets below 640 px. SectionBriefing styles live in `classroom.css`
  and were not touched.
- **Inbox** (`inboxSummaries.ts`, `useInbox.ts`, `useUnreadMessageCount.ts`).
  - One shared store per actor: one fetch path, one realtime channel and one set
    of window listeners, reference-counted.
  - Responses are sequence-guarded, so an older read cannot overwrite a newer one.
  - Other actors' idle entries are dropped when a new actor subscribes.
  - Every badge now counts unread conversations. The rail's accessible label says
    "unread conversation(s)".
  - Read receipts:
    - `useConversationMessages(id, { active })` acknowledges only the newest
      incoming message it fetched and rendered, and only while it is active and
      the tab is visible.
    - The write is a conditional update (`last_read_at IS NULL OR < watermark`)
      that returns rows and keeps microsecond precision. If no rows come back, it
      re-reads the receipt: one at or past the watermark counts as success, a
      missing membership removes the summary, and anything else throws, which
      exposes `readError` and `retryRead`.
    - The client clock is never used as a watermark. `markConversationRead` (which
      had no callers) was removed.
  - `inbox:read` and `inbox:home-cleared` are still dispatched, so
    `useInstructorMessages` still invalidates. A BroadcastChannel carries the same
    signal to other tabs.
  - Callers updated: ConversationView (`active: true`, plus a small retry line),
    MainhubHelpControl and HelpSheet (`active: open`).
