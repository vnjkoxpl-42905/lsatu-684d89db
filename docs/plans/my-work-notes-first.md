# Make My Work a useful home for teaching notes

Date: 2026-10-26. Status: proposal for Joshua's approval, not implementation authorization.

## Purpose and decision map

My Work helps a student find, read and return to Joshua's teaching notes, then find and continue assigned work. Notes are primary. Assignments are secondary but remain one obvious action away. The student's own notebook is optional and subordinate. Keep the My Work sidebar name for now; explain its purpose through visible Notes and Assigned work navigation rather than adding another global destination.

User confirmed that the current page feels hidden, purposeless and unengaging, and specifically requested navigable notes first, assigned work second and meaningful visual components. This is a redesign of this destination, not a redesign of the entire application.

## Proposed experience

1. Enter My Work on Notes when the account has classroom access or is admin. The top navigation reads Notes, Assigned work, Completed. Keep existing URLs /my-work/notes, /my-work/to-do and /my-work/completed. Implement an explicit destinationLandingPath rule rather than relying on tab order: classroom/admin -> notes; everyone else -> to-do, including Reading Center pending and fully locked states. Preserve current checking/retry/lock semantics through MyWorkGate. Reading-Center-only users retain their allowed assignments landing; permissions are not widened. Preserve query/hash and all historical links.
2. Notes opens with a useful visual shelf: a prominent recent teaching note with title, stored date, plain type label, meaningful excerpt and Read note action. Beside it, compact real totals for available notes and unread notes act as filters, not decorative statistics. On narrow screens the shelf stacks and the archive begins immediately below. Do not use an oversized hero that buries the archive again.
3. All teaching notes remain visibly browsable below the shelf, including read notes. Use tidy document cards with distinct document silhouettes, title, date, actual type and a useful excerpt. The title and card open the same detail URL. Show several cards in the first desktop viewport. A focused search field searches title and safe plain-text body; All and Unread filters are sufficient for the first release. Extract text using sanitized inert template content, never raw HTML in a live-document div. Memoize per item content/version, and prove extraction causes neither handlers nor network activity in a real browser test. No invented topic tags, generated summaries, course maps or falsely inferred session groupings.
4. The archive provides a clear result count, an explicit no-match state and Clear filters. Default order is created_at descending, id ascending as a stable tie-breaker; show that creation date on cards. Retain calendar-month headings above 12 records, using created_at, while adding search; this preserves useful chronology rather than reversing the existing grouping decision. Filtering must never mark notes read. Read state follows existing opened-detail semantics and never claims learning/mastery. Errors do not become empty results. The current hook is unpaginated; before claiming complete counts/search, implement or verify exhaustive stable paginated retrieval to avoid Supabase row caps. Render 12 cards initially with Load more, searching the complete accessible collection. Keep current identity/RLS contracts; admin counts may include extra rows because admin bypasses RLS, and must not be reported as student acceptance. Student counts require actual student data or accurately student-shaped fixtures.
5. A slim Assigned work panel offers real current work with an Open assigned work action and at most three existing actionable items. Extract the current MyWorkList visibility/status projection into a shared selector used by both views, retaining Reading Center filters, assignment-instance identity, failed/evidenceWarnings semantics and routeWithReturnTo. Show counts only after loading; label partial counts as potentially incomplete on failure, with retry. If this extraction proves disproportionately risky, ship the link alone with no count or duplicated data projection. Do not manufacture due dates, progress percentages or note-to-assignment relationships.
6. My notes is a smaller secondary control opening the existing personal notebook as a clearly separate view within Notes. Use view=mine, retaining existing ?note= IDs; legacy note links imply the personal view even without view=mine. Empty personal notes take one compact line. Preserve creation/editing. BrowserRouter cannot use useBlocker: protect Close, note switching and view switching with a dirty-state confirmation; preserve drafts synchronously in sessionStorage keyed by signed-in user ID plus note ID on each edit, recover on reload/reentry and use beforeunload for leaving the tab. Label recovered drafts as unsaved, not saved to account; failed saves retain drafts and content. Clear that item's draft only after successful server save. Never read another user's draft, never migrate routing infrastructure for this feature, and never mutate a teaching note through personal editing controls.
7. Opening a teaching note uses the current detail renderer. Archive URL state: q, filter=unread (absent means All), shown (validated bounded integer), separate from view=mine and note. Search updates replace history; filter/view actions create deliberate history entries. Card links carry an encoded returnTo restricted by validation to local /my-work/notes plus permitted archive query keys, rejecting external or protocol-relative paths. Both detail Back branches honour this target and otherwise fall back to /my-work/notes, never navigate(-1) or drop state through /classroom/recaps. Keep an opened-card anchor per archive URL in session storage; restore that card, or the nearest surviving neighbour if reading removed it from Unread, with focus and scroll. Existing Ask behavior remains. Mobile shows a full reading page with clear Back to notes; desktop keeps content readable. Shelf rendering never marks notes read.

## Visual and navigation contract

Use the existing classroom family: near-white paper, charcoal text, readable serif titles and clear sans-serif controls. Give note documents tangible but restrained depth, compact type labels and strong title hierarchy. Visible labels and active states must explain where a click leads. Use brief hover/focus feedback and reduced-motion support, never entrance motion that hides the archive while async data arrives. No carousel, horizontal-only essential navigation, ornamental charts, streaks or large empty editor. Both keyboard and touch can open each item; avoid nested interactive controls inside a linked card. Use responsive grid/reflow and a 44px practical touch-target goal.
